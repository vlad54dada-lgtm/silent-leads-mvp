# PRODUCT.md — LeadFlow

> Бриф продукту: **що** ми будуємо і **навіщо**. Як будувати — див. [CLAUDE.md](CLAUDE.md).

## 1. Суть

**LeadFlow** — система автоматизації роботи з лідами для малого бізнесу.
Всі заявки з різних джерел автоматично потрапляють в одну базу, AI оцінює кожного ліда
(пріоритет, категорія, коротке резюме), а менеджер миттєво отримує сповіщення про гарячі
ліди і веде їх по воронці продажів.

## 2. Проблема

- Заявки розкидані по формах сайту, месенджерах, таблицях — частина губиться.
- Менеджер вручну розбирається, хто «гарячий», а хто ні — реакція повільна.
- Немає історії: хто, коли і що робив з лідом; дублікати одного клієнта.
- Немає цифр: скільки лідів, з яких джерел, яка конверсія.

## 3. Ціль спринта

> **Жоден лід не губиться.** Кожна заявка автоматично потрапляє в єдину базу,
> отримує AI-оцінку пріоритету, а менеджер дізнається про гарячий лід протягом хвилини
> і веде його по воронці.

### Критерії успіху (вимірювані)

| Метрика | Ціль |
|---|---|
| Заявка з форми → збережена в БД | < 5 сек, 100% заявок (без втрат при збої AI чи Telegram) |
| Гарячий лід → сповіщення менеджеру | < 1 хв |
| Дублікати (той самий email/телефон) | зливаються в одного ліда, нова заявка — подія в історії |
| AI-оцінка | у ≥ 95% лідів є score, категорія, резюме |

## 4. Користувачі

| Роль | Що робить |
|---|---|
| **Менеджер з продажів** | Отримує сповіщення, відкриває картку ліда, змінює статус, пише нотатки |
| **Власник / керівник** | Дивиться дашборд: кількість лідів, джерела, конверсія по етапах |
| **Сайт / зовнішня система** | Надсилає заявки через webhook (машинний «користувач») |

## 5. Ключові функції

### Must have — обов'язково в цьому спринті (MVP)

1. **Прийом лідів**
   - Webhook `POST /api/leads/intake` для форми сайту (захищений секретом, ідемпотентний).
   - Ручне додавання ліда менеджером через інтерфейс.
2. **Єдина база лідів**
   - Поля: ім'я, email, телефон, компанія, повідомлення, джерело, UTM-мітки, сирий payload.
   - Нормалізація телефону/email і дедуплікація.
3. **Воронка (міні-CRM)**
   - Статуси: `new → contacted → qualified → proposal → won / lost`.
   - Список лідів з фільтрами (статус, джерело, температура) і пошуком.
   - Картка ліда: дані, AI-аналіз, нотатки, історія подій.
4. **AI-збагачення і скоринг** (Claude API)
   - Score 0–100, температура `hot / warm / cold`, категорія запиту, резюме в 1–2 речення,
     рекомендований наступний крок.
   - Виконується **після** збереження ліда; збій AI не блокує прийом заявки.
5. **Сповіщення в Telegram**
   - Менеджер отримує повідомлення про новий лід; гарячі — з позначкою 🔥 і посиланням на картку.
6. **Авторизація** — вхід для менеджерів (Supabase Auth), дані недоступні без логіну.

### Should have — якщо встигаємо

7. **Імпорт CSV** — завантаження існуючої бази з мапінгом колонок і дедуплікацією.
8. **Дашборд** — ліди за період, розподіл по джерелах, конверсія по етапах воронки.

### Won't have — свідомо НЕ робимо в цьому спринті

- Telegram-бот для прийому лідів від клієнтів, інтеграції з Instagram/Facebook Lead Ads.
- Email-розсилки і автоматичні відповіді клієнтам.
- Мультитенантність (кілька компаній), ролі і права складніші за «менеджер».
- Мобільний застосунок.

## 6. Основний сценарій (happy path)

1. Клієнт заповнює форму на сайті → сайт шле JSON на webhook.
2. LeadFlow валідує дані, нормалізує, перевіряє дублікат, **зберігає** ліда (статус `new`).
3. У фоні Claude аналізує заявку → записує score, температуру, категорію, резюме.
4. Менеджеру в Telegram приходить сповіщення (🔥 для `hot`).
5. Менеджер відкриває картку, зв'язується з клієнтом, переводить у `contacted`, додає нотатку.
6. Кожна дія пишеться в історію ліда; керівник бачить це в дашборді.

## 7. Модель даних (чернетка)

- **leads** — `id, created_at, updated_at, source, name, email, phone, company, message,
  utm (jsonb), raw_payload (jsonb), status, score, temperature, ai_category, ai_summary,
  ai_next_step, ai_status (pending/done/failed), assigned_to`
- **lead_events** — історія: `lead_id, type (created, duplicate_submission, status_changed,
  note_added, ai_enriched, notified), payload (jsonb), actor, created_at`
- **lead_notes** — `lead_id, author_id, body, created_at`

## 8. Обмеження та припущення

- Інтерфейс — українською; один бізнес (без мультитенантності).
- Персональні дані лідів — не логуються у відкритому вигляді, не потрапляють у git.
- Бюджет на AI мінімальний: один виклик Claude на ліда, модель задається через env.

## 9. Відкриті питання

- Які саме поля шле форма сайту? (поки — гнучка схема + `raw_payload`)
- Один менеджер чи кілька? Потрібен розподіл лідів між менеджерами?
- Критерії «гарячого» ліда від бізнесу (бюджет, терміновість, тип послуги?) — уточнити промпт скорингу.
